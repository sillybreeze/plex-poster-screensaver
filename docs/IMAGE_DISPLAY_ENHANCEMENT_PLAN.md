# 图片显示功能增强开发计划

日期：2026-11-05  
状态：已实施（本地提交，未推送）  
范围：切换效果选项、海报墙、无动效轮播

## 1. 目标

在保留当前单张居中海报与氛围背景作为默认体验的前提下，增加可配置的海报切换效果、一次显示多张海报的海报墙，以及完全静止的轮播模式。配置由文件和命令行控制；现有预取、缓存、缩放调整、暂停和退出行为继续适用。

这三项功能应彼此组合，而不是变成互斥的显示模式列表：布局选择单张或海报墙；切换效果选择淡化或方向滑入；动效模式选择正常或静止。静止模式优先级最高，会关闭布局切换动画和 Ken Burns，但不会停止按设定间隔更换内容。

## 2. 当前实现基线

- `src/render.rs` 的 `Composition` 包含一张按比例完整显示的海报、全屏氛围背景和居中位置；当前海报不会被裁切。
- `src/app.rs` 的 `Phase` 处理 Idle、旧新画面的淡入淡出以及 Ken Burns 动画。`fade_seconds` 控制现有淡入淡出，`ken_burns` 控制单张海报缩放。
- 每个 `Slide` 只含一张 `Composition`；预取线程通过容量为 1 的通道交付一张画面。
- `src/gpu.rs` 的 `Textures` 和像素着色器绘制全屏背景及一张海报。尺寸变化会取消旧预取任务并重新构建目标分辨率画面。
- `--no-motion` 当前只关闭 Ken Burns，不关闭淡入淡出。本计划将它明确扩展为静止轮播快捷选项。

## 3. 建议的配置界面

文件配置新增以下字段：

```json
{
  "display_layout": "single",
  "transition": "fade",
  "transition_seconds": 0.6,
  "motion_mode": "animated",
  "ken_burns": true
}
```

字段定义与默认值：

| 字段 | 可用值 | 默认值 | 行为 |
| --- | --- | --- | --- |
| `display_layout` | `single`、`wall` | `single` | 单张海报或 6 张海报的 3×2 海报墙 |
| `transition` | `fade`、`slide_left`、`slide_right`、`slide_up`、`slide_down`、`random` | `fade` | 每次更新画面的切换方式；方向值描述画面从哪一侧进入中央 |
| `transition_seconds` | 0.1–3.0 秒 | 0.6 秒 | 淡化或滑入时长；静止模式忽略此值 |
| `motion_mode` | `animated`、`static` | `animated` | `static` 关闭切换动画和 Ken Burns，但仍按 `display_seconds` 轮播 |
| `ken_burns` | 布尔 | `true` | 仅在 `animated` 模式下启用单张布局的缓慢缩放 |

CLI 新增 `--layout single|wall`、`--transition fade|slide-left|slide-right|slide-up|slide-down|random` 和 `--motion animated|static`。现有 `--no-motion` 作为 `--motion static` 的别名保留。命令行优先于配置文件。`--fade` 保留为旧参数别名，用于设置 `transition_seconds`，避免已有启动脚本失效；帮助文本注明它也控制方向滑入时长。

兼容规则：旧配置没有新字段时，维持 `single`、`fade` 和 `animated` 默认行为；旧配置中的 `ken_burns: false` 仍表示只关闭缩放，不关闭淡入淡出。CLI `--no-motion` 是明确的静止模式快捷方式，会同时关闭淡入淡出、滑入和 Ken Burns。

## 4. 实施阶段

### 阶段 A：配置模型与输入验证

**目标文件：** `src/config.rs`、`src/main.rs`、`config.example.json`、`README.md`。

**实现方式：**

- 新增强类型枚举 `DisplayLayout`、`Transition` 和 `MotionMode`，解析 JSON 与 CLI 时统一转为枚举，不在帧循环中解析字符串。
- 扩展 `Args`、`FileConfig`、`Config::default()` 和参数覆盖逻辑，保持 CLI > 环境/文件配置 > 默认值的既有优先级；新字段不增加环境变量，除非项目现有约定要求。
- 校验未知枚举值及 `transition_seconds` 非有限值、负值和越界值，错误信息指出 JSON 键或 CLI 参数。默认范围为 0.1–3.0 秒；静止模式也验证输入，避免同一配置只因模式切换而潜藏无效值。
- `--no-motion` 覆盖 `motion_mode=animated`；`--motion` 可以显式选择 `animated` 或 `static`，按命令行顺序无关地应用优先级。
- 更新示例配置与 README 的参数说明和配置优先级示例。

**验收：**

- 旧配置不修改即可维持旧显示效果。
- JSON 与 CLI 的合法值均能解析；未知模式、NaN/Inf 和越界时长在创建窗口前以配置错误退出。
- 验证 `--no-motion` 与 `--motion static` 等价，且 CLI 可覆盖 JSON 配置。

### 阶段 B：方向切换效果

**目标文件：** `src/app.rs`、`src/gpu.rs`，必要时 `src/render.rs`。

**实现方式：**

- 扩展帧阶段为统一的切换阶段，保存旧帧、旧 UV、切换起始时间、新帧及所选方向；保留现有 fade 作为一种转场。
- 为 GPU 绘制入口增加图层位置偏移参数，或提供等价的 `draw_at`，不修改纹理实际尺寸。方向滑入时先从屏幕边缘外开始，使用平滑缓动插值到 Composition 的原始居中位置；开始与结束坐标都根据海报宽高和画面尺寸计算，确保最初完全离屏，结束精确居中。
- 过渡期间每帧先画旧场景，再按过渡进度绘制新场景。单张布局移动海报图层并对场景做淡化混合；海报墙布局移动完整的墙面画布。结束后释放旧纹理并进入常规停留/缩放阶段。
- `random` 在每张新画面开始时选一次方向，不得在每帧重新随机；若可选方向多于一个，避免与上一次方向连续重复。方向选择使用可单测的纯函数，不把随机性放入着色器。
- 过渡时长由 `transition_seconds` 控制；设为 `fade` 时与原淡入淡出职责一致。移除 `Phase::Fade` 后，确认首次显示没有旧纹理时直接显示，不做无意义的空场转场。
- `motion_mode=static` 时不进入转场阶段，直接切换到新帧；正常动画帧率仍沿用现有 `motion_fps`，避免新增独立帧率配置。

**验收：**

- 左、右、上、下四种方向均从画面外进入并准确停在中央，无越界残影、尺寸抖动或闪黑。
- 随机方向在一张海报的整个过渡期间保持稳定；大量切换测试不会在动画中途改变方向。
- `fade` 与旧配置的视觉行为相当；首次画面直接就位。
- 过渡期间输入退出、系统暂停、GPU 恢复和窗口尺寸变化仍按既有路径处理，旧纹理不会被重复释放。

### 阶段 C：海报墙布局

**目标文件：** `src/app.rs`、`src/render.rs`、`src/gpu.rs`、`src/plex.rs`。

**实现方式：**

- 将显示帧从“恰好一张海报”提升为布局帧：单张布局继续使用现有背景/海报图层；海报墙布局由预取任务交付一组海报和布局参数。
- 首版固定使用 **6 张、3 列×2 行**。边距与卡片间距随目标画面尺寸按比例确定并设最小像素值；每张海报按比例 fit 到自己的格子，不裁切、不变形、不覆盖邻卡，空白使用统一的低对比背景色。
- 在预取线程中从现有 Section 缓冲池取得 6 个不重复的条目，优先复用缓存；缓存未命中时通过现有 Plex 下载与解码流程补齐。网络、图片解码、缩放和合成全部留在预取线程，UI 线程只上传已经完成的帧纹理。
- 不新增每张海报单独的同步网络请求路径；复用现有 HTTP 超时、取消代次、缓存索引和离线条目筛选。取消/尺寸改变后，旧代次必须停止提交组帧结果。
- 在 worker 中生成屏幕尺寸的海报墙画布。增加全帧上传/绘制类型，使 GPU 能把合成画布当作完整场景做淡化或方向滑入；不要把整屏逐像素合成放在主线程，也不要让一个 4K 全屏 CPU 缓冲在每个动画帧重复重建。
- Plex 可用条目不足 6 张时显示可用数量并按网格重新分配；可用数量为 1 时退回单张，不画空卡占位。在线下载部分失败时，以成功缓存/解码的海报继续组帧；全部失败时沿用当前无内容等待与错误状态，不显示空白墙。
- 海报墙停留期间不换单张卡片，整体按 `display_seconds` 作为一个场景切换；随机布局只在组帧时生成一次，避免一张墙在过渡或停留时不断洗牌。
- 尺寸变化时依据新尺寸重建画布与网格，沿用当前任务代次与 worker 取消逻辑；缓存里存储原始/服务端缩图，不把按分辨率合成的墙面画布当作某一条媒体的封面缓存。

**验收：**

- 验证 6 张正常、1–5 张短列表、重复候选、坏缓存、部分网络失败、全离线以及无可播放缓存等场景。
- 所有海报保持纵横比与可读性，格子不重叠；目标分辨率至少覆盖 1280×720、1920×1080 和 3840×2160。
- 墙面在停留期间保持不变；切换完成后旧组纹理能释放，连续轮播不会累积 GPU/CPU 内存。
- 用 `--preview` 及 `--snapshot` 检查布局输出；为快照路径增加所选布局支持，或提供等价的无 UI 画布导出，避免只验证单张实现。
- 人为延迟网络并触发暂停、尺寸变化或取消时，主线程不因获取墙面条目而阻塞，旧尺寸/旧代次墙面不会显示。

### 阶段 D：无动效轮播

**目标文件：** `src/config.rs`、`src/app.rs`、`src/render.rs`、`README.md`。

**实现方式：**

- `motion_mode=static` 下忽略 `transition`、`transition_seconds` 与 Ken Burns 进度；每次到达 `display_seconds` 后直接替换当前帧。
- 单张布局保持当前的海报位置与氛围背景，只显示静止图像；海报墙布局也允许静止显示并按间隔整体更换下一组。
- 在静止模式下仅安排内容切换、宽限期、状态检查等需要的事件截止时间，不按 `motion_fps` 反复唤醒，不重画同一帧。
- 保持 `--no-motion` 对静止模式的快捷语义；保留 `ken_burns:false` 作为只禁用缩放、仍可用转场的细分设置。

**验收：**

- 通过录屏/帧计数验证画面在一张内容的整个停留时间内像素稳定，没有滑动、淡入、缩放或持续重绘。
- 到达 `display_seconds` 后仍能自动切换下一张/下一组；切换不等待输入事件。
- 静止模式中按 ESC、键鼠活动收起、托盘退出和系统暂停恢复均正常。
- 用调试帧统计确认静止单张模式不以 `motion_fps` 运行，并且 idle 到下一张时没有忙循环。

## 5. 自动测试与手动验收矩阵

自动测试至少包括：

- 配置枚举解析、默认值、CLI 覆盖、旧配置兼容、非法值与范围校验。
- 转场函数：四方向起点/终点、边界外完全不可见、缓动单调、完成时精确归位、随机方向在单次动画内稳定。
- 海报墙布局：0–6 张输入、单元格边界、宽高比、非重叠、少量海报自适应和无重复项。
- 帧状态机：首帧无转场、fade 与 slide、静止模式跳过动画但保留停留计时、换尺寸/取消/暂停时纹理生命周期正确。
- 现有缓存与离线测试仍全量通过；墙面下载取消不得覆盖新代次索引或托盘状态。

手动验收使用真实 Windows 桌面与项目的 `--preview`：

1. 单张布局分别查看淡化和四种方向滑入，确认海报完整、中央对齐，快速连按退出/切换不崩溃。
2. 海报墙检查正常与少于 6 张、离线缓存、至少三个分辨率以及连续尺寸调整。
3. 静止模式运行多个轮播周期，确认完全无动效但持续换图，显示器缩放、最小化恢复和输入退出正常。
4. 组合测试海报墙 + 随机方向、海报墙 + 静止模式、单张 + `ken_burns=false`，确认三类设置互相独立且静止模式优先。
5. 在 1920×1080 与 3840×2160 观察过渡帧率、GPU 占用与内存；对照单张默认模式确认没有明显性能退化。

## 7. 推荐开发顺序

1. 阶段 A 先落定相互独立的配置与旧行为兼容。
2. 阶段 B 在单张布局完成并手工验收，再扩展统一场景接口支持海报墙。
3. 阶段 C 在 worker 组帧和 GPU 全帧上传通过后接入切换效果；先固定 3×2，暂不增加用户自定义行列数。
4. 阶段 D 最后统一静止模式对所有动画分支的优先级和调度，减少同一功能多处判断。
5. 每阶段独立提交并更新交付记录；海报墙场景纹理生命周期和静止模式低唤醒是合入前重点检查项。

### 8.3 关键实现

- 配置：新增 `DisplayLayout`、`Transition`、`MotionMode` 强类型枚举；JSON 字段 `display_layout`、`transition`、`transition_seconds`、`motion_mode` 与既有 `ken_burns` 组合。CLI 新增 `--layout`、`--transition`、`--motion`；`--no-motion` 等同 `--motion static`；`--fade` 保留为 `transition_seconds` 别名。旧 `fade_seconds` 配置继续读取，`transition_seconds` 优先。
- 校验：未知枚举值、NaN/Inf、负数和越界时长在创建窗口前报错；错误信息包含 JSON 键或 CLI 参数名；`--no-motion` 与 `--motion static` 与参数顺序无关。
- 转场：`Phase::Transition` 统一保存旧帧、旧 UV、开始时间与实际效果；GPU uniform 增加背景偏移与背景/海报两层独立 alpha；单张布局移动海报层并淡化背景，海报墙移动整张画布；随机方向每张只选一次且避免连续重复；首帧、静止模式、`transition_seconds=0` 直接切换，转场帧率沿用 `motion_fps`。
- 海报墙：新增 `src/layout.rs` 负责 3×2/短列表网格、边距与间距下限、比例 fit；worker 逐张复用缓存或下载并合成整屏画布，主线程只上传一张纹理；少于 6 张按可用数量重排，1 张退回单张，全部失败沿用等待/错误状态。
- 静止：`motion_mode=static` 跳过转场与缩放；停留帧只绘制一次，不再按 `motion_fps` 反复唤醒或重复 Present；调度只保留换图、宽限期和常驻输入检查截止时间；最小化恢复、尺寸变化与系统恢复强制重画一帧。
- GPU 恢复：纹理创建失败现在携带 `GpuError`，设备丢失时直接进入既有退避恢复，避免静止模式长时间不 Present 导致上传失败无限重试。

### 8.5 已知行为变化与限制

- `--no-motion` 的语义由“只关 Ken Burns”扩展为完全静止（关闭淡化/滑入/缩放）；只想关闭缩放请使用配置 `ken_burns: false`。
- 新默认转场时长为 0.6 秒（旧默认 1.2 秒）；旧配置若显式写了 `fade_seconds` 会按原值映射，超过 3 秒或 0–0.1 秒之间会报错。
- 海报墙固定最多 6 张、3 列×2 行，不支持自定义行列；短列表按 2×1、3×1、2×2、3×2 自动重排。
- 墙面画布每次组帧在 worker 生成，不写入媒体缓存；4K 下每帧约 33 MB，连续切换的内存峰值高于单张布局。
- 随机方向只在换图时生成一次；同一进程内使用时间种子，不保证跨进程可复现。
